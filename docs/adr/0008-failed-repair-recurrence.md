# ADR 0008: Count evidenced failed repairs as repeated mistakes

Status: implemented without pseudo-stage canonicalization, issue29;67 analyzer/resource checks,43 CLI checks and native-fixture syntax pass. Prior113/66-test passes are historical, not semantic acceptance. Independent final review, native and complete-history acceptance remain pending.

## Evidence

The owner explicitly selected count_failed_repairs. Fresh substantive feedback after an attempted same-cause code fix is another mistake, even while completing one repair. This supersedes the independent-original-defects-only convention in ADR0001/0003/0005/0006, not the threshold of two or causal evidence requirements. Frozen Reel PR146 contains initial title feedback, a partial title fix and fresh feedback on remaining error paths; duplicate inline/review reports of the same post-fix state still count once. Historical strict-old-contract audits do not establish acceptance of all53 proposals: unrelated mechanisms, over-prescribed remedies and provenance defects remain material.

## Decision

Change consolidation policy/context and remove mechanical same-thread stage guesses. Supply each admitted member's original comment body, kind, creation time, thread/path and originalCommitId once alongside the complete catalog/current findings. Diff hunks are code artifacts, not global metadata: supply them and noneligible same-thread/PR review-discussion context only for current-delta PRs. Deduplicate actual source/patch artifacts into shared per-PR tables, including cross-file fixes and pathless reviews. Available empty source has a real equality fingerprint; unavailable source has none. Those fingerprints deduplicate literal evidence, not causal stages. Do not truncate; the existing input budget applies before every call. Keep v6 classification, citation feedback, finding hashes, capture/output/checkpoint schemas and resource/privacy boundaries unchanged. Changed grouping instructions/context naturally invalidate prior grouping state without modifying historical caches.

Supply complete captured source/patch tables only for PRs represented by the CURRENT delta, including every captured earlier version and cross-file/pathless review evidence. Keep all original member commentary and each original finding's cause/prevention/resolution/evidence in the complete catalog. Finished PRs retain metadata, not repeatedly transmitted full code. codeContext states this boundary explicitly: consolidation is not a new full-code review of every old PR. Batch, restore and final structural canonicalization preserve model-assigned memberships with deterministic IDs/order; they do not infer or merge causal stages. If active PR evidence plus complete catalog/commentary cannot fit, fail before the call without truncation or an automatic limit increase; the16MiB adapter ceiling is not a model-context promise.

An occurrence may be an original defect or fresh substantive feedback after an evidenced relevant attempted repair. A new PR/thread/time/SHA, unrelated change, unchanged repost, acknowledgement or duplicate review is not another mistake. One minimal preventive invariant must explain every occurrence and its accepted observed resolution. Explain the original/failed-repair distinction and evidence rather than inferring a repair from chronology alone.

A captured originalCommitId can remain the old anchor on a fresh reply, not identify the current reviewed version. A comment's timestamp has finite precision; equal times do not prove unchanged code or preclude an actual repair. Neither original-ref/hunk equality, a matching caller, differing bytes nor reconstructed post-image windows can certify the whole current causal state. Remove the stage-guess helpers and deterministic same-thread merge veto rather than add timestamp exceptions. Model assignments/explanations establish the actual relevant attempt, fresh substantive feedback, current-state linkage and accepted resolution from original commentary and captured changes, including delegated-file patches without delegated-file snapshots. Model existingIncidentIndex assignments join duplicate reports; no source/thread/time heuristic overrides them. Unchanged, unrelated, duplicate or unsubstantiated feedback must not create recurrence, but enforcing that is causal judgment, not a universal deterministic NLP gate. Missing/squashed commits, misleading author dates or missing current-state links must not be filled in. No new witness field or per-comment causal-facet protocol is introduced.

Keep exact target partition, snapshot-index references, paired refinement, collision checks, whole-batch atomic checkpoints, final coverage and two-supported-occurrence threshold. No temporal framework, handwritten classifications, cache edits, new options, provider calls or main merge.

The earlier pseudo-stage approaches failed actual review: full-source substring containment suppressed additive repairs; differing anchor pairs defeated duplicate ceilings; unchanged callers suppressed delegated repairs. Parent then reproduced f9 collapsing an actual partial repair at equal second-precision timestamps from2occurrences to1. Reviewer also identified valid disjoint policy patches whose post-images never differ at overlapping lines, and removal-only attempts with empty post-images. These failures justify deleting the inference machinery, not reconstructing versions or adding more metadata rules. Preserve the a5/f9 red evidence. Controlled consumer fixtures now supply their semantic memberships explicitly; native26/2600 duplicate handling and the old-anchor delegated repair remain actual-model expectations, not mocked split-then-clamp guarantees.
