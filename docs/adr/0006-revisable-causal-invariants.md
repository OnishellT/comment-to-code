# ADR 0006: Revise causal hypotheses without losing evidence

Status: accepted implementation decision, issue25; native and complete-history semantic acceptance blocked pending provider reset.

## Evidence

The complete 45-rule Reel audit found 8 endorsements, 17 revisions, 9 rejections and 11 pending judgments. A separate Opus saved prefix still reused a disconnect-only invariant for token refresh. Freezing the first hypothesis prevents a later independent resolution from correcting its scope. These preserved real counterexamples are the failure evidence; no provider retry is needed to reproduce them.

## Decision

Supersede only ADR0005's immutable invariant restriction. A referenced existing group may inherit both rootCause and prevention with null/null, or replace both with nonempty owned-marker-free strings. Reject partial pairs, blanks and owned markers before cloning or checkpointing. Preserve every old incident/member and add each current finding exactly once through the existing snapshot references and canonical validation.

Require one minimal preventive core supported by every old and new observed resolution. Reword a false case-specific hypothesis; do not append incident-specific AND clauses, generalize to a topic, impose a rejected remedy, or merge distinct interventions. Different implementations can enforce the same core. No old-group repartition, explanation rewrite, second judge, repair, runtime gate, schema addition or provider-setting change.

The actual instructions already participate in the consolidation fingerprint, so old policy checkpoints naturally restart. Do not rehash old state or invalidate unchanged v6 findings. Existing privacy, complete coverage, captured-thread deduplication and two-independent-incident publication protections remain unchanged.
